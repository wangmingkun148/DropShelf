DropShelf 3.1.7 修好了 3.1.6 里置物架点不动的问题。

### Linux 版

- **置物架上的开关、按钮又能点了**：有的 X11（XWayland）程序——WPS 就是这样——拖完东西以后不把手里的拖动交回来，系统一直以为还在拖。3.1.6 的 X11 拖放桥看到这个就提前把接放窗口挂了出来，那是一块铺满整个屏幕的透明窗口，置物架上所有的点击都被它吃掉了，顶上的“复制/移动”开关、`×`、`⋯` 全都没反应。现在只有真的按着左键在拖的时候才挂这个窗口，平时不会挡住置物架；看不到按键状态的设备照旧，不会影响正常的 X11 拖动。
- **仓库只发布 Linux 版**：Release 工作流里的 Windows 打包作业整段注释掉了（Windows 的编译检查还在 Build 工作流里），以后这里只出一个 Linux 安装包和一个 `v` 开头的标签。
- 打包依赖里补上了 `appstream`，`appstreamcli` 检查校验文件时不会再提示缺命令。

### 升级

- Linux：AppImage 下载后 `chmod +x` 再运行；deb/rpm/pacman 用发行版的包管理器升级；便携版解压后运行 `bin/dropshelf`。

遇到问题欢迎到 [Issues](https://github.com/pingod/DropShelf/issues) 反馈，请附上 `~/.local/state/dropshelf/logs` 里的日志。

DropShelf 3.1.7 fixes the shelf not responding to clicks in 3.1.6.

### Linux

- **The copy/move switch and the buttons on the shelf work again**: some X11 (XWayland) apps — WPS, for one — never hand back the drag after you drop something, so the system keeps believing a drag is in progress. The X11 drop bridge added in 3.1.6 saw that and put its catch window up early. That window covers the whole screen invisibly, so it swallowed every click on the shelf: the “copy/move” switch at the top, `×` and `⋯` all did nothing. The catch window is now only put up while the left button is actually held, so it stays out of the way otherwise; devices that cannot report the button state behave as before, so normal X11 drags are unaffected.
- **This repository only publishes the Linux version**: the Windows packaging job in the Release workflow is commented out (the Windows build check stays in the Build workflow). From now on there is one Linux package and one `v` tag.
- `appstream` was added to the packaging dependencies so `appstreamcli` no longer warns about a missing command while checking the AppStream file.

### Upgrading

- Linux: `chmod +x` the AppImage and run it; use your distribution's package manager for deb/rpm/pacman; unpack the portable tarball and run `bin/dropshelf`.

If you run into a problem, please open an [issue](https://github.com/pingod/DropShelf/issues) with the logs from `~/.local/state/dropshelf/logs`.
