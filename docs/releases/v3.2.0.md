DropShelf 3.2.0 修好了移动模式下往 WPS 拖没反应，复制模式拖出的东西也会留在架上了。

### Linux 版

- **移动模式拖到 WPS 里能放下了**：WPS 这类文档程序只肯接受“复制”、拒绝“移动”，3.1.9 的 X11 拖动源在移动模式下提议移动，被拒以后就取消了这次拖出，看起来一点反应都没有。现在被拒就改成复制重新进入一次，图片、文件照样插进文档里。
- **复制模式拖出的项目留在置物架上**：以前开着“自动关闭空置物架”时，拖出去的项目会离开架子，拖走最后一个时架子还会自己关掉。现在只有按“移动”拖出的项目才离开（对方只肯复制时也算移动），复制出去的总留在架上，可以再拖到别处。设置里这项的说明也跟着改了。

### 升级

- Linux：AppImage 下载后 `chmod +x` 再运行；deb/rpm/pacman 用发行版的包管理器升级；便携版解压后运行 `bin/dropshelf`。

遇到问题欢迎到 [Issues](https://github.com/pingod/DropShelf/issues) 反馈，请附上 `~/.local/state/dropshelf/logs` 里的日志。

DropShelf 3.2.0 fixes dropping onto WPS in move mode and keeps copied items on the shelf.

### Linux

- **Dropping onto WPS works in move mode again**: document apps like WPS only accept "copy" and refuse "move". In move mode the X11 drag source added in 3.1.9 proposed a move, got refused and cancelled the drag, so nothing seemed to happen. It now re-enters with copy after a refusal, and the image or file is inserted into the document as before.
- **Items dragged out with Copy stay on the shelf**: with "Close empty shelves" on, dragged-out items used to leave the shelf and taking the last one closed it. Now only items dragged out in Move mode leave (including when the target only copies), while copied items always stay so you can drag them somewhere else as well. The setting's description was updated to match.

### Upgrading

- Linux: `chmod +x` the AppImage and run it; use your distribution's package manager for deb/rpm/pacman; unpack the portable tarball and run `bin/dropshelf`.

If you run into a problem, please open an [issue](https://github.com/pingod/DropShelf/issues) with the logs from `~/.local/state/dropshelf/logs`.
