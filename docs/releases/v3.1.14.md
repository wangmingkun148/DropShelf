DropShelf 3.1.14 修好了从置物架往 WPS 这类 XWayland 程序拖东西时的几个问题（文字带上剪贴板、文件和文字一起拖只进去图片、拖很长的文字把整个桌面带崩），给混合拖出加了“自动分批”模式；置物架的分类汇总也换成了彩色标签，点一下只看这一类。

### Linux 版

- **文件和文字一起拖出不再丢掉文字**：置物架里同时选中图片和文字拖到 WPS 这类文档程序时，以前文字会被写成 `.txt` 跟着文件列表一起给，但文档程序只肯插入图片，`.txt` 被它忽略。现在新增的“自动分批”（默认）会按置物架里的顺序一项一项地拖出去：先放下图片，再自动把文字单独送过去，WPS 两种都能收下。“智能”则把文字和图片合成一份 HTML 一起交，放下后再补送一批纯文字。也可以在设置 → 置物架 → 混合拖出里改成“只送文件”或“只送文字”，另一种留在置物架上。分批只在拖到 X11（XWayland）程序时生效，具体见下一条。
- **能一次收到所有内容的程序照旧**：拖到原生的 Wayland 程序时拿到的还是完整的一次拖动（图片等文件加文字的 `.txt`），没法也不需要自动分批；分批和 HTML 只用在拖到 WPS 这类 XWayland 程序的时候。
- **拖进 WPS 的文字不再带上剪贴板**：之前拖出时，WPS 会同时看到 Hyprland 转过去的拖动和我们自己发的 X11 拖动两个来源，于是有时会退回粘贴剪贴板，“低洼地”这类内容就跟在拖过去的文字前面一起出现了。现在复制模式（以及文字、链接这种本来就不能移走的）保留 Hyprland 的那次拖动，只接过它的数据 selection，由我们把拖出去的内容直接交给接收方；移动模式仍用自己的 X11 拖动源。
- **快速拖放也不会退回剪贴板**：复制模式看到光标下的 XWayland 程序就立刻接管，不再等半秒多；拖动途中 selection 被别人抢回去时会马上拿回来。
- **连续拖出不会再卡住**：拖到 WPS 这类程序时 GTK 常常收不到结束通知，上一轮拖动会一直挂着，拖几次以后就再也拖不出来。现在新的按下会先把挂着的旧拖动取消掉，迟到的结束通知也不会再打乱正在进行的拖动。
- **拖很长的文字不再把整个桌面带崩**：GTK 默认把拖出去的整段文字做成拖动图标里的一个标签。文字很长时这个标签宽得（多行时也高得）离谱，拖动图标窗口跟着变成几千像素，显卡驱动直接报 Xid 13（3D HEIGHT CT Violation）并重置显卡通道；在这块 NVIDIA 显卡上紧接着 OpenGL 上下文失效、DropShelf 段错误，Hyprland 收拾它挂着的拖动时又 abort，整个桌面一起没了。现在文字拖动只显示开头 32 个字符的图标。另外 Linux 版默认改用 Cairo 软件渲染——置物架和设置窗口本来就小，不再碰显卡；自己在环境变量里指定了 `GSK_RENDERER` 的仍按指定来。挂着的拖动也会在 1.5 秒后自动取消，不再长时间挡住新的拖入。

### 置物架

- **分类汇总变成彩色标签**：收起时显示在叠起来的卡片下面，展开后显示在列表上方，每一类一个颜色（文件用强调色、文件夹用橙色、文本用绿色、链接用紫色），深浅两套主题各自调整过。数量写在标签上，比如“2 个文件”。只有一类时不显示标签，仍然直接写项目自己的名字。
- **点标签只看这一类**：点某个标签，置物架上就只剩这一类；收起状态下点会顺便展开列表。叠起来的卡片、标题和大小汇总也按这一类算。再点同一个标签恢复全部；展开以后列表上方的标签一直都在，随时能换一类或者取消。
- **筛选时只作用于看得见的项目**：选中、拖出、右键菜单、Ctrl+A、Delete 都只对筛出来的项目生效，架子外面藏着的那些不受影响；换筛选或取消筛选会清掉之前的选中。把某一类全部删掉或者移走以后，自动回到显示全部。
- **两种风格都有**：简洁和纸牌风格都换成了彩色标签，纸牌风格下标签跟着卡片配色。

DropShelf 3.1.14 fixes several problems when dragging from the shelf into XWayland apps like WPS (clipboard content being inserted along with the text, only the image arriving when files and text are dragged together, and dragging very long text taking the whole desktop down), adds an "Auto batches" mode for mixed drags, and turns the shelf's category summary into colored tags: click one to show only that kind, click it again to show everything.

### Linux

- **Text is no longer lost when files and text are dragged out together**: selecting an image and some text on the shelf and dragging both into a document app like WPS used to send the text along as a `.txt` file in the file list, which document apps ignore — only the image was inserted. The new default "Auto batches" mode drags the items out one at a time in shelf order: the image is dropped, then the text is sent on its own, and WPS accepts both. "Smart" combines the text and images into a single HTML payload and follows up with the text. You can also switch the Shelf → Mixed drag-out setting to "Files only" or "Text only" and leave the other kind on the shelf. Batching only applies when dragging onto X11 (XWayland) apps; see the next item.
- **Native Wayland targets still get everything at once**: dragging onto a native Wayland app still delivers one complete drag (images and other files plus `.txt` files for the text), so there is nothing to batch and no way to synthesize extra Wayland drags. Batching and the HTML payload are used only for XWayland apps like WPS.
- **Dragged text no longer brings the clipboard into WPS**: the target used to see two drag sources at once — the one Hyprland forwards and the separate X11 source we created — and could fall back to pasting the clipboard, so text like "低洼地" showed up before the dragged text. Copy-mode drags (and text or links, which cannot be moved anyway) now leave Hyprland's drag in place and only take over its data selection, handing the dragged content straight to the receiver. Move mode still uses our own X11 drag source.
- **Fast drops no longer fall back to the clipboard**: copy mode takes over as soon as the cursor is over an XWayland app instead of waiting more than half a second, and takes the selection back immediately if something else grabs it mid-drag.
- **Dragging out repeatedly no longer gets stuck**: GTK often misses the end of a drag onto apps like WPS, leaving the previous drag hanging until no further drag can start. A new press now cancels the hung drag first, and late end notifications no longer disturb the drag in progress.
- **Dragging very long text no longer takes the whole desktop down**: by default GTK turns the entire dragged string into a label inside the drag icon. For a very long string that label becomes thousands of pixels wide (and very tall when it has many lines), so the drag icon window grows to match and the GPU driver raises Xid 13 (3D HEIGHT CT Violation) and resets the graphics channel. On this NVIDIA card the OpenGL context then became invalid and DropShelf segfaulted; Hyprland aborted while cleaning up the drag left hanging, which took the entire desktop with it. Text drags now show only the first 32 characters in the drag icon. The Linux build also uses the Cairo software renderer by default — the shelf and settings windows are tiny, so it no longer touches the GPU at all (an explicit `GSK_RENDERER` still wins). A hung drag is still cancelled automatically after 1.5 seconds instead of blocking new drops for a long time.

### Shelf

- **The summary is now colored tags**: shown under the stacked cards when collapsed and above the list when expanded, one color per kind (files use the accent color, folders orange, text green, links purple), tuned separately for light and dark themes. The count is part of each tag, such as "2 files". With only one kind there are no tags — the item's own name is shown as before.
- **Click a tag to show only that kind**: the shelf keeps just that kind, and clicking while collapsed expands the list at the same time. The stacked cards, title and size summary count only that kind too. Clicking the same tag again shows everything; once expanded, the tags above the list stay put so you can switch kinds or clear the filter at any time.
- **Filtered actions only touch what is visible**: selection, drag-out, the context menu, Ctrl+A and Delete act only on the filtered items, never on the ones hidden by the filter; changing or clearing the filter clears the previous selection. Removing every item of a kind automatically returns to showing all of them.
- **Both styles**: the simple and cards styles both use the colored tags, with the cards style picking tag colors that go with its cards.

### Upgrading

- Linux: `chmod +x` the AppImage and run it; use your distribution's package manager for deb/rpm/pacman; unpack the portable tarball and run `bin/dropshelf`.

If you run into a problem, please open an [issue](https://github.com/pingod/DropShelf/issues) with the logs from `~/.local/state/dropshelf/logs`.
